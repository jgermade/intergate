# intergate-tunnel: the client as a service, per-user limits, ports from the client

Status: in progress on branch `ccr-6176c116-87z07i` (PR open). Everything
below is built, tested and pushed except "Next".

## The ask

setup.sh should offer to install a client service that keeps connections
open. Refined in conversation: a separate, light `intergate-tunnel` binary;
one service per machine for all tunnels, on one or several gates
(web1.gate.example1.com:8080, web2.gate.example2.com:8090); a terminal
wizard; the client may list, create and change a subdomain's ports with its
key; admins/owners limit each user's subdomains and extra ports, optionally
to port ranges ("ana has 2 ports in 30100-30109,30200-30299"); the dashboard
keeps reserving ports. Then: the desktop app's window in the dashboard's
design.

## What was built

- Limits per user (`internal/manage/limits.go`, migration 7): subdomains,
  ports and port ranges, NULL = the configuration's. `tcp.max_ports` now
  counts per user across subdomains. Admin → Users: a sliders button opens
  the limits dialog. A port may ask for its public number within the
  owner's ranges. Lowering a limit keeps what exists.
- `internal/wire`: SSH global requests `info@intergate`,
  `port-add@`, `port-update@`, `port-delete@intergate`, JSON in and out
  (errors in the reply, since SSH failures carry no message). Handled in
  `internal/sshd/portreqs.go` through `manage`, so limits and checks are the
  dashboard's. Creating needs an allow list (`any` for anyone). Ports record
  `created_by` (migration 8), shown in the dashboard.
- `internal/client`: `Info`, `AddPort`, `UpdatePort`, `DeletePort`, `Dial`,
  `Discover` (moved from clientapp), and `*.localhost` resolved to loopback.
- `internal/agent` + `cmd/intergate-tunnel`: `tunnels.yaml` by gate,
  machine key, `add/remove/allow/ports/status/key/install/uninstall/run`,
  `run HOST` ad hoc (also behind `intergate tunnel`). Daemon with SIGHUP
  reload and a status file. systemd (system user `intergate-tunnel`,
  hardened unit; or `--user`), launchd on macOS (LaunchDaemon as root or
  LaunchAgent). `setup` wizard (huh, `--accessible`).
- Distribution: `intergate-tunnel-<target>` archives in build.yml (CI checks
  it doesn't pull in the server), setup.sh `client` / `uninstall-client`
  and menu options, tunnel.sh `--install [--user]`.
- Desktop app window redrawn with the dashboard's theme and components,
  served from the new `internal/web/ui` package (nonce CSP); state follows
  changes by revision (no missed updates between long polls).

## Verified

go test -race ./..., scripts/setup-check.sh, shellcheck; by hand against a
dev server: dashboard limits UI, CLI add/wait-for-key/ports/allow/remove,
daemon reload, accessible wizard, the app window (screenshots).

Not verified on real machines: `install` with systemd and with launchd (unit
and plist are unit-tested only), the app on Windows itself, the full-screen
wizard beyond a pty smoke test.
